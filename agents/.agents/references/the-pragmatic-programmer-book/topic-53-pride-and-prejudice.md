## Topic 53: Pride and Prejudice

Pragmatic programmers take pride in their work by taking personal responsibility for the code they produce and signing their names to it. Software developers hold significant power as code weaves into daily life, which requires developers to act with vigilance and maintain a strong moral compass. Developers must take ownership of software quality and commit to building ethical systems that protect users from harm.

### The Pragmatic Approach

- **Sign your work**: Put your name on your code as a seal of quality, craftsmanship, and accountability.
- **Practice mutual respect**: Treat other developers' code with respect rather than building insular fiefdoms or territorial boundaries.
- **Support shared ownership**: Embrace team or communal ownership of code to eliminate anonymity while avoiding territorial isolation.
- **Protect the user**: Ensure every implementation protects users from harm, security vulnerabilities, and unexpected failures.
- **Maintain a moral compass**: Refuse to build unethical features or enable harmful practices. Ask whether you would comfortably use the software yourself.

### Common Mistakes

- **Hiding behind anonymity**: Viewing oneself as a cog in the wheel, leading to sloppy work, sloth, and weak excuses in status reports.
- **Defending code territorially**: Becoming prejudiced in favor of your own code while resisting collaboration with team members.
- **Neglecting user safety**: Delivering code without evaluating potential harm, security gaps, or failure modes in critical systems.
- **Enabling unethical requests**: Rationalizing participation in harmful or invasive software projects instead of exercising the courage to say no.
