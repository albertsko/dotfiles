## 18. Power Editing

Editor fluency lets software engineers translate ideas into code without interrupting their reasoning to manage editing mechanics. Fluency means navigating text and syntax precisely, applying common transformations efficiently, searching and editing repeated patterns, managing multiple views, and running project feedback from the keyboard. Build fluency incrementally: notice repetitive work, learn the command, integration, or extension that removes it, and practice until the action becomes automatic.

### The Pragmatic Approach

- Observe each editing session and record repetitive actions, mouse-dependent steps, and apparent limitations; treat each one as a prompt to find a faster command or extension.
- Navigate and select by character, word, line, paragraph, and code structure such as matching delimiters, functions, and modules.
- Use dedicated commands to reindent changed code, comment or uncomment blocks, sort selected lines, and undo or redo changes.
- Work without leaving the keyboard: split the editor into panels, move between them, and jump directly to a line number.
- Search for literal strings and regular expressions, repeat previous searches, and use temporary multiple cursors to update every selected or matching occurrence in parallel.
- Display compilation errors and run project tests inside the editor so feedback stays beside the code being changed.
- Keep a list of tools and artifacts that would improve the editing workflow, then look for integrations that bring them into the editor.
- Practice one useful command many times each day for about a week to build muscle memory.
- Turn off key autorepeat to learn precise movement, selection, and deletion commands; work without a mouse or trackpad for one week to expose gaps in keyboard fluency, and record the key sequences you learn.
- Learn every editor you use well enough to perform frequent tasks without thinking about mechanics; focus on useful commands rather than memorizing the entire command set.
- Search for an extension when the editor lacks a needed capability; consider switching editors if the capability remains unavailable.
- Learn the editor's extension language and automate recurring work with a small script when no suitable extension exists.
- Build and publish a full extension when a recurring need justifies it and the solution could help other engineers.
