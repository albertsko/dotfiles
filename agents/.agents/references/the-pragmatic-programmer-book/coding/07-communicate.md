## 7. Communicate!

Effective software engineering depends on communicating intent clearly to people and through code and documentation. Treat natural language with the same discipline as code: define the purpose, adapt the content, timing, and style to the audience, seek feedback, listen, respond reliably, and present information accurately. Build documentation into development by documenting public interfaces and recording why decisions and trade-offs were made while letting the code explain how the implementation works.

### The Pragmatic Approach

- Define the result you want from each document, meeting, or conversation, identify the audience, and outline the essential points before drafting.
- Frame the same technical decision around each audience's priorities. Explain user-visible interoperability to users, operational ownership to managers, and application programming interface opportunities to developers.
- Choose a receptive moment and make the message relevant to current priorities. Ask, “Is this a good time to discuss the source code repository?” before starting an important conversation.
- Match the format, detail, and tone to the audience's knowledge and preferences. Ask whether they need a concise factual briefing or a deeper explanation, and explain when the requested format cannot convey the necessary detail.
- Test whether the audience received the intended meaning. Invite questions, observe reactions, ask people to restate key decisions in their own words, and adjust the explanation when their response reveals a gap.
- Share early drafts with the intended readers. Use their feedback to correct assumptions and improve the final document before decisions harden.
- Listen before advocating a position. Ask questions and turn presentations and meetings into dialogues so concerns and missing information can shape the solution.
- Acknowledge messages and requests promptly, even when the full answer must come later. State when the sender can expect the follow-up, then deliver it.
- Present written communication with consistent structure and clean formatting. Proofread spelling and meaning, keep quoted material brief and attributed, verify recipients, and avoid sending language that you would not use face to face.
- Keep documentation close to the code and generate reference material from module and exported-function comments where practical. Document purpose, constraints, trade-offs, rejected alternatives, and reasons; avoid comments that merely repeat the implementation or create a second description that must be maintained.
