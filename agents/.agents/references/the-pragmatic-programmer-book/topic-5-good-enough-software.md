## Topic 5: Good-Enough Software

Real-world constraints like time, technology, and budget make bug-free, perfect software impossible to achieve. Striving for absolute perfection delays delivery and often produces worse software. Pragmatic developers aim for "good-enough" software, which fulfills user requirements, security, privacy, and performance standards without unnecessary delay.

### The Pragmatic Approach

- **Make quality a requirements issue**: Discuss scope, delivery constraints, and software quality trade-offs directly with users during requirements gathering.
- **Involve users in trade-offs**: Deliver working software early so users can test it and provide feedback to guide future iterations.
- **Know when to stop**: Refrain from overrefining code. Let software stand on its own once it satisfies the required standards.

### Common Mistakes

- **Chasing impossible perfection**: Postponing releases to add unnecessary features or polish code repeatedly.
- **Equating good-enough with sloppy code**: Sacrificing basic engineering practices, security, privacy, or core requirements under the guise of "good enough".
- **Ignoring user constraints**: Overlooking business deadlines, user needs, and cash-flow constraints to pursue internal developer preferences.
