## Topic 3: Software Entropy

Software entropy measures disorder within a software system, commonly called software rot or technical debt. Project psychology and neglect accelerate software rot faster than any other factor. The Broken Window Theory explains how unrepaired flaws trigger rapid systemic decay. A single left-unrepaired flaw signals abandonment, encouraging team members to introduce further sloppy code. Pristine code produces the opposite effect, motivating developers to maintain high quality even during urgent crises.

### The Pragmatic Approach

- Fix broken windows immediately upon discovery.
- Board up known flaws with comments, dummy data, or stubs if an immediate full fix is impossible.
- Avoid causing collateral damage when working under tight deadlines or resolving crises.
- Maintain code quality proactively to protect project culture against disorder.

### Common Mistakes

- Leaving bad designs, wrong decisions, or poor code unrepaired.
- Ignoring small flaws due to perceived lack of time, allowing entropy to spread uncontrollably.
- Adopting a sloppy mindset because existing code already contains flaws.
- Causing unnecessary collateral damage across the codebase during emergency fixes.
