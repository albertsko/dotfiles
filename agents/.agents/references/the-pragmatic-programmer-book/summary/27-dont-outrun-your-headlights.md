## 27. Don’t Outrun Your Headlights

Software development has a limited throw distance: the farther plans reach beyond current evidence, the more educated estimates turn into speculation. Move in small, deliberate steps and treat the rate of independent feedback, such as results from a read-evaluate-print loop (REPL), unit tests, user demonstrations, and conversations, as the speed limit for progress. Design only as far ahead as evidence allows; when the future is uncertain, make code easy to replace, which encourages cohesive, loosely coupled, and less duplicated designs. Rare, unpredictable events can overturn confident assumptions, while cognitive biases can hide changes at the edges of the work, so never count on tomorrow resembling today.

### The Pragmatic Approach

- Break work into small, deliberate steps.
- Seek independent feedback after every step, then adjust before proceeding.
- Limit each task to the scope that available feedback can validate.
- Avoid plans that depend on distant completion dates, maintenance needs, user demands, or technology forecasts.
- Design only for needs supported by current evidence.
- Make uncertain code easy to discard and replace.
- Revisit assumptions and watch for rare events or overlooked changes.
