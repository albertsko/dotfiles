## 47. Working Together

Working together means collaborating with users, developers, testers, and sponsors while writing code, not merely collecting input through meetings, notes, or exhaustive documentation. A system tends to mirror its team's communication structure, so including users in development makes their knowledge visible in the software, while isolated teams tend to produce siloed designs. Deliberately structuring the team and its communication can guide the code toward the desired structure. Pair programming places two developers on one problem with one person typing and the other considering broader concerns, combining perspectives, attention, accountability, and mental capacity; mob programming extends the same live-coding collaboration to a larger, diverse group for difficult problems. Solo, pair, mob, co-located, and remote work can all be effective, so teams that have used only one style should experiment with another.

### The Pragmatic Approach

- Include users, testers, sponsors, and other relevant experts in live coding sessions.
- Keep users and domain experts available for questions, clarifications, decisions, and demonstrations throughout development.
- Try pair programming for at least two weeks in sessions lasting only a few hours, because it may feel strange at first.
- Keep both developers engaged with the problem during pair programming, and switch typing duties as needed.
- Start with only a few pairs or a small mob of four or five people, and keep sessions short.
- Use mob programming to brainstorm ideas, diagnose difficult problems, or solve hard problems.
- Rotate the typist in a mob every five to ten minutes.
- Start with a simple exercise before applying a new collaboration style to critical production code.
- Focus on building the code rather than defending your ego, criticize the code rather than the person, and listen to different viewpoints.
- Hold frequent retrospectives and adjust the collaboration process.
- Study the guidelines, benefits, and pitfalls of each collaboration style through both instructional material and experience reports before adopting it.
