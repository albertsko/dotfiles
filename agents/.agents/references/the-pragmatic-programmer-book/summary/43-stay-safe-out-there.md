## 43. Stay Safe Out There

Working code is not finished until developers analyze both accidental failures, including bad parameters and leaked or unavailable resources, and deliberate abuse, then add corresponding tests. Treat every internet-connected system as exposed because obscurity offers no protection. Security starts with reducing the attack surface: keep code simple; validate and sanitize all external input; authenticate services or explicitly limit unauthenticated access; prevent unintended public data-store exposure; minimize authorized accounts; replace default credentials; protect deployment credentials; reveal only appropriately authorized output; and hide debugging data. Grant each program and user the least privilege needed for the shortest time, partition access finely, and make default settings the most secure while allowing users to make explicit convenience tradeoffs. Encrypt personally identifiable information, financial data, passwords, and credentials, and keep secrets and keys out of version control by managing them separately in deployment configuration. Encourage long, random passwords; support at least 64 characters, preferably up to 256; accept all printable ASCII characters, spaces, and Unicode; and avoid truncation, composition rules, disabled paste, unauthenticated hints, or forced rotation without a valid reason such as a breach. Apply security patches quickly to every connected device and system despite compatibility costs. Never implement cryptography yourself; use well-vetted, thoroughly examined, maintained, frequently updated, preferably open-source libraries and frameworks. Delegate authentication to a specialized provider when appropriate. If you must implement authentication, understand password hashing and salting, rainbow-table attacks, why MD5 and SHA-1 are unsuitable, and the security and legal obligations of holding credential data.

### The Pragmatic Approach

- Analyze how code can fail accidentally, including bad parameters and leaked or unavailable resources, or through deliberate abuse, then add those cases to the test suite.
- Keep code and services small, simple, and limited to the access points the system needs.
- Treat all external input as hostile, and validate and sanitize it before storage, rendering, execution, or other processing.
- Authenticate services where appropriate, limit unauthenticated access to reduce denial-of-service risk, and prevent unintended unauthenticated public access to data stores.
- Minimize authorized users and services, remove unused or outdated accounts, replace default credentials, disable unprotected administrative accounts, and protect deployment credentials.
- Return only data appropriate to each user's authorization, obscure sensitive identifiers, and protect stack traces and debugging facilities.
- Grant the least privilege required, hold elevated access for the shortest possible time, and divide sensitive resources into fine-grained permission categories.
- Choose the most secure defaults, then let users explicitly accept convenience tradeoffs.
- Encrypt sensitive data at rest, and manage secrets, keys, and credentials outside version control through deployment configuration or environment variables.
- Encourage long, random, high-entropy passwords; support at least 64 characters, preferably up to 256; accept all printable ASCII characters, spaces, and Unicode; and avoid truncation, composition rules, paste restrictions, unauthenticated hints, or forced rotation without a valid reason such as a breach.
- Apply security patches quickly to every connected device, development system, build system, server, and deployed image.
- Never implement cryptography yourself; use well-vetted, thoroughly examined, maintained, frequently updated, preferably open-source libraries and frameworks.
- Delegate authentication to a specialized provider when appropriate. If you must implement it, understand password hashing and salting, rainbow-table attacks, why MD5 and SHA-1 are unsuitable, and the security and legal obligations of holding credential data.
